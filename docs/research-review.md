# Related work on diagnosing LLM context

**Scope search on 19 November 2026.** The question was which existing systems expose source-level context problems at runtime, find them across traces, or test how a context change affects an outcome. This is a targeted scoping review of work relevant to the implementation. Coverage is limited to sources found and verified under the searches below.

### Counterfactual values in question answering

Longpre and colleagues substituted an answer entity in a passage to evaluate whether a QA model followed the new evidence. Subsequent work on multiple passages studied conflicting contextual answers alongside a model’s parametric knowledge. Both are related methods. The journal experiment adapts value substitution to two named workflow instructions. It records the complete answer under each edit. A different answer can still disagree with the replacement, as the follow-up question illustrates. [Longpre et al., EMNLP 2021](https://aclanthology.org/2021.emnlp-main.565/) · [Rich Knowledge Sources Bring Complex Knowledge Conflicts, EMNLP 2022](https://aclanthology.org/2022.emnlp-main.146/) · [Workflow experiment](guide.md#does-the-answer-follow-an-edited-value)

### Comparing experiments that share a declared target

EleutherAI’s Language Model Evaluation Harness already scores a supplied continuation and reports whether greedy decoding follows its tokens. We use this established measurement to compare named source edits at the same answer boundary. The sidecar shows the first position where another vocabulary token outscores the target and joins matching edits to separately generated full answers. In the fresh journal example, both target digits led and the model still appended a unit. This small experiment tests the distinction between prefix support and exact-output success. [Evaluation Harness model interface, v0.4.7](https://github.com/EleutherAI/lm-evaluation-harness/blob/v0.4.7/docs/model_guide.md#interface) · [Four-question experiment](guide.md#which-edit-moved-a-target-token-to-the-top-before-generation)

On 20 November 2026 we checked CheckList and Langfuse’s experiment documentation for overlap with the target-miss feature. Ribeiro et al. organize behavioral tests by capability and test type. Langfuse already supports expected outputs, dataset items drawn from production traces, aggregate comparisons, and inspection of individual failures. Both are related work. NexusWeave uses a narrower unit for its recurring recommendation. Each experiment binds a set of verified edits to named context sources. The sidecar counts conversations where every tested condition missed, and links each count to the actual proposals. We have not compared the tools in a user study. [CheckList, ACL 2020](https://aclanthology.org/2020.acl-main.442/) · [Langfuse datasets](https://langfuse.com/docs/evaluation/experiments/datasets) · [Langfuse experiment comparisons](https://langfuse.com/docs/evaluation/experiments/compare-experiments)

## Tool selection under changes to context

On 20 November 2026 we followed up with the search `Berkeley function calling leaderboard irrelevant function tools relevance detection BFCL` and checked the primary papers on tool-set changes and hidden-state probes returned by that search.

Rabinovich and Anaby-Tavor studied how function selection responds to query variations and the addition of semantically related tools on an expanded BFCL subset. Their study makes tool availability a direct comparison point. NexusWeave crosses tool definitions with instruction text on one captured request, then repeats the same user edit in each setup. Its four-row result concerns that request and runner. BFCL measures function-calling performance across tasks. Both are related research. The NexusWeave example uses synthetic requests. [Rabinovich and Anaby-Tavor, 2025, v1](https://arxiv.org/abs/2504.00914v1) · [BFCL, ICML 2025](https://proceedings.mlr.press/v267/patil25a.html)

Yeats et al. trained linear probes on model hidden states to detect incorrect tool calls across 18 models. This approach needs instrumented states and labels for errors. It addresses whether a call is likely incorrect. A controlled replay asks whether the proposed call changes under a specific input intervention. [Yeats et al., 2026, v1](https://arxiv.org/abs/2608.27750v1)

The calendar experiment uses source order as a control and compares its pre-generation forecast with a direct rule that chooses the source named by the user. The two rules tied across the four matched question pairs. [Experiment and saved evidence](methods.md#does-the-suggested-edit-follow-the-question-when-source-order-changes)

## Repeatability and outcome choice

A follow-up search on 20 November 2026 used `LLM evaluation prompt sensitivity decoding randomness repeated sampling`. Hua et al. found that the apparent sensitivity of performance to prompt templates depended on how answers were scored. This bears on our choice to report a change in the complete proposal and a change in the selected tool separately. Both outcomes describe captured behavior. Correctness and downstream task success require their own criteria. [Hua et al., EMNLP 2025](https://aclanthology.org/2025.emnlp-main.1006/)

ReliableEval estimates how many meaning-preserving prompt resamplings an evaluation needs. Our pilot fixes one request and varies the sampling seed within a declared decoding configuration. The dashboard reports observed counts and missing comparisons. Four seeds on one input cannot establish how often an effect will recur on another input or runner. [Lior et al., Findings of EMNLP 2025](https://aclanthology.org/2025.findings-emnlp.594/) · [Fixed protocol and measurements](../examples/runtime-comparison/pending-routing/sampled.md)

## Attribution and experimental methods

Wang et al. found discrepancies between first-token rankings and generated text on multiple-choice tasks with instruction-tuned language models. NexusWeave scores the full token sequence of each supplied continuation. Unscored alternatives can still receive substantial probability. The warranty check therefore compares score reversals with freely generated answers and reports the probability outside the specified pair. [Wang et al., Findings of ACL 2024](https://aclanthology.org/2024.findings-acl.441/) · [NexusWeave experiment](methods.md#what-do-model-scores-add-before-generation)

A 20 November follow-up searched the ACL Anthology for `surface form competition highest probability answer` and ICML proceedings for `calibrate before use`. Holtzman et al. show how valid alternative wordings compete with the specified answer strings. Zhao et al. show that prompt format and examples can bias the choice between answers. Both are related methods. NexusWeave displays the remaining probability outside a named pair, compares source edits at one fixed prefix, and checks the literal starts of free generations. Its probabilities come directly from the scorer. The eight-question study includes an answer where the correct number follows a quotation mark. [Holtzman et al., EMNLP 2021](https://aclanthology.org/2021.emnlp-main.564/) · [Zhao et al., ICML 2021](https://proceedings.mlr.press/v139/zhao21c.html) · [Experiment](methods.md#can-a-supplied-answer-prefix-identify-a-source-worth-testing)

Liu et al. varied where relevant information appeared in multi-document question answering and key-value retrieval and found position-sensitive performance in long contexts. Their intervention motivates holding content constant and varying order. The NexusWeave demo tests two short source messages, reverse order and the same single-source edits on each side. It measures sensitivity of the scored output in that design. Long-context retrieval accuracy and internal attention require their own measurements. [Lost in the Middle, TACL 2024](https://aclanthology.org/2024.tacl-1.9/)
