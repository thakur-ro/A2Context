# Related work on diagnosing LLM context

**Scope search on 19 November 2026.** The question was which existing systems expose source-level context problems at runtime, find them across traces, or test how a context change affects an outcome. This is a targeted scoping review of work relevant to the implementation. Coverage is limited to sources found and verified under the searches below.

### Learned failure categories and state-based evaluation

The MAST release supplies traces with 14 failure-mode labels. The scalable labels come from a model annotator. A separate human-labeled set supplies a smaller check. AdaMAST in ATLAS already learns categories from traces, checks exact spans, and uses approved categories for runtime reflection. It is a candidate source for failure labels and proposed repairs. A2Context's evaluation binds a source edit to a request and checks the measured outcome separately. [MAST paper](https://proceedings.neurips.cc/paper_files/paper/2025/hash/b1041e52d3be19f0a9bc491657488e4a-Abstract-Datasets_and_Benchmarks_Track.html) · [Pinned MAST data](https://huggingface.co/datasets/mcemri/MAST-Data/tree/95118ac951421753cf1deb87ddea3b01e693c41b) · [Pinned ATLAS runtime](https://github.com/multi-agent-systems-failure-taxonomy/ATLAS/tree/546687ad2289d3fe4865b7e02aa2413c8b99821b)

Who&When supplies human annotations of the decisive step in failed multi-agent traces. Who&When Pro creates failures by editing a known step and continuing from the original prefix. TRIAGE records ranked candidate failures and variation across judgments on Who&When. These labels support different tests. A2Context uses the injected steps to measure when tool errors become visible in a trajectory. Attribution to a source in a particular request still requires the request and a verified source intervention. [Who&When](https://proceedings.mlr.press/v267/zhang25cq.html) · [Who&When Pro](https://arxiv.org/abs/2607.09996v1) · [TRIAGE](https://aclanthology.org/2026.aacl-short.27/) · [Action-evidence evaluation](recommendation-loop.md#seventh-pass-check-when-a-failure-becomes-visible)

AppWorld supplies a simulator and evaluates task outcomes with programmatic state checks. A2Context uses the simulator's tool implementations for two controlled transfers and checks their task-specific state changes. The published AppWorld task suite has its own instructions and evaluators. [AppWorld paper](https://aclanthology.org/2024.acl-long.850/) · [Transfer study](recommendation-loop.md#fifth-pass-compare-the-operation-with-the-source-change)

### Checking a restored decision

Pakhomov and Nijkamp propose checking restored continuations against the live continuation before attributing behavior to agent history. Their experiment found that two restores could agree with each other while diverging from the live run when the random stream was restored incorrectly. In the watchlist study we checked the unchanged third prompt and generated output against the preceding experiment in every natural condition, then repeated all 16 crossed requests. This supports repeatability for the observed greedy checkpoint. A stochastic production runner would need its own restoration and outcome checks. The reporting standard and CAR are related work. A2Context has yet to validate an integration with CAR. [Pakhomov and Nijkamp, November 2026](https://arxiv.org/abs/2611.05650v1) · [Watchlist controls](../examples/bfcl-transfer/mlx/watchlist/checkpoint/protocol.md)

### Counterfactual values in question answering

Longpre and colleagues substituted an answer entity in a passage to evaluate whether a QA model followed the new evidence. Subsequent work on multiple passages studied conflicting contextual answers alongside a model’s parametric knowledge. Both are related methods. The journal experiment adapts value substitution to two named workflow instructions. It records the complete answer under each edit. A different answer can still disagree with the replacement, as the follow-up question illustrates. [Longpre et al., EMNLP 2021](https://aclanthology.org/2021.emnlp-main.565/) · [Rich Knowledge Sources Bring Complex Knowledge Conflicts, EMNLP 2022](https://aclanthology.org/2022.emnlp-main.146/) · [Workflow experiment](guide.md#does-the-answer-follow-an-edited-value)

### Evaluating whether retrieved context can answer a question

Joren and colleagues define context sufficiency, evaluate an automated judge against human judgments, and use that signal in selective generation. Their repository publishes the judge prompt. This is the closest comparison for a pre-answer sufficiency alert. Our experiment uses a much smaller Qwen checkpoint, a single YES/NO scoring pass, and paired inventories with source-level evidence annotations. The question is whether that cheaper signal can select a useful intervention. The authors’ benchmark results describe a different model, prompt and evaluation set. [Joren et al., ICLR 2025](https://research.google/pubs/sufficient-context-a-new-lens-on-retrieval-augmented-generation-systems-2/) · [Pinned author repository](https://github.com/hljoren/sufficientcontext/tree/801b465eb3be5bf5216fbe3301e61daee85ff99c) · [Our paired test](../examples/public-qa/support-review/README.md)

For source-removal controls, Trivedi et al. already compared deleting supporting facts with deleting a non-supporting fact and extended the construction to equalize fact counts. MuSiQue also includes deliberately unanswerable contrast questions. Our reviewed-passage experiment addresses an additional practical case in retrieval logs. Several different passage sets can each support an answer, so the target edit intersects each recorded set. The matched control edits the same number of passages. This evaluates a particular model on those edits. [Contrastive support sufficiency, EMNLP 2020, §4.2 and Appendix A.3](https://aclanthology.org/2020.emnlp-main.712/) · [MuSiQue, TACL 2022](https://aclanthology.org/2022.tacl-1.31/) · [Selection protocol](../examples/public-qa/support-review/witness-edits/protocol.md)

### Comparing experiments that share a declared target

EleutherAI’s Language Model Evaluation Harness already scores a supplied continuation and reports whether greedy decoding follows its tokens. We use this established measurement to compare named source edits at the same answer boundary. The sidecar shows the first position where another vocabulary token outscores the target and joins matching edits to separately generated full answers. In the fresh journal example, both target digits led and the model still appended a unit. This small experiment tests the distinction between prefix support and exact-output success. ## Tool selection under changes to context

On 20 November 2026 we followed up with the search `Berkeley function calling leaderboard irrelevant function tools relevance detection BFCL` and checked the primary papers on tool-set changes and hidden-state probes returned by that search.

Rabinovich and Anaby-Tavor studied how function selection responds to query variations and the addition of semantically related tools on an expanded BFCL subset. Their study makes tool availability a direct comparison point. A2Context crosses tool definitions with instruction text on one captured request, then repeats the same user edit in each setup. Its four-row result concerns that request and runner. BFCL measures function-calling performance across tasks. Both are related research. The A2Context example uses synthetic requests. [Rabinovich and Anaby-Tavor, 2025, v1](https://arxiv.org/abs/2504.00914v1) · [BFCL, ICML 2025](https://proceedings.mlr.press/v267/patil25a.html)

Yeats et al. trained linear probes on model hidden states to detect incorrect tool calls across 18 models. This approach needs instrumented states and labels for errors. It addresses whether a call is likely incorrect. A controlled replay asks whether the proposed call changes under a specific input intervention. [Yeats et al., 2026, v1](https://arxiv.org/abs/2608.27750v1)

The calendar experiment uses source order as a control and compares its pre-generation forecast with a direct rule that chooses the source named by the user. The two rules tied across the four matched question pairs. [Experiment and saved evidence](methods.md#does-the-suggested-edit-follow-the-question-when-source-order-changes)

McCoy, Pavlick and Linzen tested whether natural-language inference models could succeed through heuristics such as lexical overlap. We used their comparison as motivation for including a word-overlap baseline alongside a task-specific semantic lookup. The activity study examines whether an edit changes the generated duration. The lookup identified the intended activity in 16/16 cases, while editing that record changed only seven resolved durations. [McCoy et al., ACL 2019](https://aclanthology.org/P19-1334/) · [Activity study](../examples/context-screening/replay/prefix-indirect/README.md)

## Repeatability and outcome choice

For the November 20 exchange follow-up, we searched for `Berkeley Function Calling Leaderboard multi-turn execution state` and `grammar-constrained decoding structured NLP tasks`. BFCL V3 already compares simulated state after execution. CAREFUL-Bench adds intermediate effects. Geng and colleagues constrain generation with formal grammars, and XGrammar provides an open implementation for structured decoding. These are related approaches. The A2Context experiment supplies only the opening tool-call marker and leaves every later token to the model. The comparison tests whether changing the start is sufficient to recover the requested call under one parser and dispatch policy. [BFCL V3 evaluation](https://gorilla.cs.berkeley.edu/blogs/13_bfcl_v3_multi_turn.html) · [CAREFUL-Bench v2](https://arxiv.org/abs/2611.02978v2) · [Geng et al., EMNLP 2023](https://aclanthology.org/2023.emnlp-main.674/) · [XGrammar v0.1.27](https://github.com/mlc-ai/xgrammar/tree/v0.1.27) · [Frozen intervention](../examples/exchange-approval/dispatch-study/prefill-tool/protocol.md)

A follow-up search on 20 November 2026 used `LLM evaluation prompt sensitivity decoding randomness repeated sampling`. Hua et al. found that the apparent sensitivity of performance to prompt templates depended on how answers were scored. This bears on our choice to report a change in the complete proposal and a change in the selected tool separately. Both outcomes describe captured behavior. Correctness and downstream task success require their own criteria. [Hua et al., EMNLP 2025](https://aclanthology.org/2025.emnlp-main.1006/)

ReliableEval estimates how many meaning-preserving prompt resamplings an evaluation needs. Our pilot fixes one request and varies the sampling seed within a declared decoding configuration. The dashboard reports observed counts and missing comparisons. Four seeds on one input cannot establish how often an effect will recur on another input or runner. [Lior et al., Findings of EMNLP 2025](https://aclanthology.org/2025.findings-emnlp.594/) · [Fixed protocol and measurements](../examples/runtime-comparison/pending-routing/sampled.md)

## Attribution and experimental methods

Wang et al. found discrepancies between first-token rankings and generated text on multiple-choice tasks with instruction-tuned language models. A2Context scores the full token sequence of each supplied continuation. Unscored alternatives can still receive substantial probability. The warranty check therefore compares score reversals with freely generated answers and reports the probability outside the specified pair. [Wang et al., Findings of ACL 2024](https://aclanthology.org/2024.findings-acl.441/) · [A2Context experiment](methods.md#what-do-model-scores-add-before-generation)

A 20 November follow-up searched the ACL Anthology for `surface form competition highest probability answer` and ICML proceedings for `calibrate before use`. Holtzman et al. show how valid alternative wordings compete with the specified answer strings. Zhao et al. show that prompt format and examples can bias the choice between answers. Both are related methods. A2Context displays the remaining probability outside a named pair, compares source edits at one fixed prefix, and checks the literal starts of free generations. Its probabilities come directly from the scorer. The eight-question study includes an answer where the correct number follows a quotation mark. [Holtzman et al., EMNLP 2021](https://aclanthology.org/2021.emnlp-main.564/) · [Zhao et al., ICML 2021](https://proceedings.mlr.press/v139/zhao21c.html) · [Experiment](methods.md#can-a-supplied-answer-prefix-identify-a-source-worth-testing)

Liu et al. varied where relevant information appeared in multi-document question answering and key-value retrieval and found position-sensitive performance in long contexts. Their intervention motivates holding content constant and varying order. The A2Context demo tests two short source messages, reverse order and the same single-source edits on each side. It measures sensitivity of the scored output in that design. Long-context retrieval accuracy and internal attention require their own measurements. [Lost in the Middle, TACL 2024](https://aclanthology.org/2024.tacl-1.9/)
