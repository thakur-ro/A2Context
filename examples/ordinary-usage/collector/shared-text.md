# Does recurring prompt text supply identifiers for an answer?

The Collector source chain printed the same three IDs on every question. None labeled the retrieved Collector passages. To test source influence without building a detector for these IDs or LangChain’s prompt, freeze the following selection and intervention before running new generations.

Use the final recorded provider reply from each completed session across all three development pilots (six workflows, five sessions each). Only consider complete, plain-text chat requests ending in one textual answer and containing no available tools. Within each workflow, compare each eligible input with the most recent earlier eligible input from a different conversation having the same model, role sequence, organization and user. The earlier call must have ended before the current one began. A different question is necessary. Pairwise shared text may include repeated evidence as well as instructions.

In corresponding messages, find the identical prefix and suffix up to whole-line boundaries, without overlap. Fully identical messages may match. In the answer, take up to three distinct ASCII identifiers containing both a letter and a digit, with a hyphen or underscore, in order of appearance. Include an identifier only when it appears as a complete token in shared input text and never in the other parts of this request. Ignore vocabulary, HTTP destination substrings and pure numbers. Exclude calls without eligible identifiers. Record both calls and exact UTF-8 input and output locations. The procedure does not read the application name, source labels, expected answers, benchmark annotations or other sessions’ outputs to select a match.

For each selected call replace all occurrences of the selected identifiers inside its matched text. Derive collision-free aliases from the call and original token, preserving ASCII length, case, punctuation and digit positions. Leave the question, varying retrieved content and every other input character unchanged. Run the original, an unchanged repeat and the edited request at seeds 11, 29 and 47, temperature 0.5, with a 512-token maximum. Shuffle arm order. Count a strict switch only when both controls reproduce the same original token and the edit produces its matching alias without that original token. Report all candidates, unanswered calls, failures, controls that disagree, and results by workflow. A switch supports influence of the jointly edited identifiers on emitted text. It does not establish the answer’s factual correctness or isolate individual tokens within a joint edit.

The [results and limitations](README.md#did-changing-the-shared-text-change-the-reply) report 22 strict switches in 24 question–seed pairs. To recheck every published location against the original captures, run `check.py --captures` followed by the six source directories. The default `check.py` validates the published counts offline.
