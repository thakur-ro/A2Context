# Does supplying the opening tool-call tag change the proposed and executed action?

Use all eight previously observed native Nous requests from the four exchange orders and their stale/refreshed cache settings. The freely decoded replies were all text. This experiment intervenes at the assistant continuation boundary of these known negative examples. It tests whether a supplied structural opener changes what runs downstream. [Request and expected outcome definitions](../prospective/README.md) · [Rendering comparison](../rendering/README.md)

Reconstruct the unedited native Nous prompt from Qwen-Agent 0.0.34 and the pinned Qwen2.5-0.5B-Instruct tokenizer. Compare two arms in order. The empty-prefix arm decodes freely. The second arm appends exactly the ASCII string `<tool_call>` followed by one LF after the existing assistant role marker. The prefix contains no tool name, field, order ID, consent or expected action. Require encoding the complete extended prompt to equal the original input IDs followed by the separately encoded prefix. Freeze SHA-256 of the rendered text and token IDs, actual token counts and the prefix IDs for both arms before fresh local inference. [Pair manifest](design.json) · [Input reconstruction](freeze.py)

Keep the total assistant token allowance at 128 in both arms, including the caller-supplied prefix and the eventual EOS. Debit every prefix token from the remaining free-generation budget. Use the same four-thread CPU float32 model with greedy decoding, same native Nous parser, validation, registered tools, checkpoint and approval gate as the original. Record both generated suffix and exact parser input, reconstructed as the supplied prefix followed by the decoded suffix excluding EOS. Open tags without a model-generated closing tag remain visible in the audit. Keep truncations unscorable and skip their callbacks. No retries or tool-format normalization.

Regenerate all eight empty-prefix and eight supplied-prefix arms in the predeclared order. The negative control requires all empty-prefix outputs and complete native SQLite receipts to reproduce the prior native run. Audit hand-built valid approved and held calls under both gates plus ordinary text as a null input. Replay each generated string through the actual parser and both SQLite gate policies. Retain every parser disposition and distinguish detected expected name, validated arguments, exact expected tool and arguments, and agreement with the full expected two-order database state. Count paired restorations, losses, unchanged states and unscorable comparisons under both gates. Count one generated response per input and prefix, independent of the two gate settings.

Repeat all eight supplied-prefix generations in a fresh process. Report tokens from the model separately from caller-supplied tokens and include decoding times. A forced prefix cannot establish that the model would have selected a tool on its own, reveal internal reasoning, or establish an operational repair on new customers. All orders and actions are synthetic and local.
